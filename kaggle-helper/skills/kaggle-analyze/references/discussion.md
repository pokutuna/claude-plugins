# discussion の分析

あなたは Kaggle で公開されている discussion を分析する専門家である。リポジトリで取り組んでいるコンペで高い成果を上げるための調査として、discussion の内容を分析する。

## 読むもの

対象のディレクトリにある次のファイル。

- `discussion.md`: 取得した discussion の本文とコメント。`## Comments (N)` の N はコメントの件数
- `analysis.md`: 既存の分析。あれば読む

## 分析の手順

1. discussion の話題と内容を把握する
2. 会話の流れから、重要なポイントと発見を抽出する。次の点に着目する
   - 主要な議論内容と疑問点
   - 提案された解決策やアプローチ
   - 検証結果や実験データ
   - 技術的な知見や洞察
   - データの特性とドメイン知識
   - 外部データとリソースの情報
   - 意見が分かれた場合の賛成意見と反対意見
3. 内容をまとめる
   - あくまで発言者の意見であることに注意してまとめる
   - 特徴的な発言は `> 発言者名: 発言内容` の形式で引用する

## 既存の analysis.md があるとき

- 既存の内容と `discussion.md` を比べ、新しいコメントや追加の議論を把握する
- `## 要約` と `## 内容` は、`discussion.md` に合わせて書き直してよい。既存の記述が `discussion.md` と食い違うときは、`discussion.md` に合わせて直す
- `## コメント・メモ` の既存の行は消さずに残す
- `## コメント・メモ` に、今回の日付 (ローカル時刻) と追記した内容の要約を 1 行足す

## コメントの読み込みを打ち切っているとき

`## Comments (N)` の下に打ち切りの注記があれば、コメントは N 件までしか読めていない。どのコメントが読めたかは分からず、新しいコメントが含まれるとは限らない。`## コメント・メモ` に次の行を書く。

```
- コメントの読み込みを打ち切り: N 件まで
```

## テンプレート

既存の `analysis.md` が無ければ、このテンプレートで書く。`## コメント・メモ` は、書くことが無ければ空でよい。

```
URL: 

## 要約
<!-- 100~200 文字程度、discussion の内容や発見・意見を簡潔に -->

## 内容

## コメント・メモ
```
